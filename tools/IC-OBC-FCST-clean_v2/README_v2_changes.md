# IC-OBC-FCST-clean v2 longitude-convention changes

This directory is a safe copy of `tools/IC-OBC-FCST-clean`.  The original
workflow directory is intentionally unchanged.

## Why v2 exists

The reforecast IC/OBC workflow already uses NEP curvilinear coordinates
(`geolon/geolat`, `geolon_u/geolat_u`, and `geolon_v/geolat_v`) and keeps
`periodic=False` and `flood=False` in the active OBC paths.  However, the
source and target longitude conventions were mixed when xESMF weights were
built:

- NEP source static grid longitudes are in 0-360 convention:
  - `geolon`: about 156.9 to 255.0
  - `geolon_u`: about 156.9 to 255.0
  - `geolon_v`: about 156.9 to 255.0
- GoA target grids were in -180 to 180 convention:
  - `GOA_STATIC geolon*`: about -158.7 to -129.9
  - `GOA_HGRID x`: about -158.7 to -129.9

v2 converts both source and target longitudes to 0-360 before xESMF weight
generation so the GoA target longitudes are expected to print around 201.3 to
230.1.

## Files changed

- `standalone/boundary/BGC/OBC_BGC.py`
  - Converts `NEP_STATIC["geolon"]` to 0-360 before attaching source lon/lat.
  - Converts `hgrid["x"]` to 0-360 before creating BGC OBC `Segment` objects.
  - Prints source, target hgrid, and segment longitude ranges.
- `standalone/boundary/PHY/write_CGOA_boundary_2Dfrc-padded.py`
  - Converts `NEP_STATIC["geolon"]`, `NEP_STATIC["geolon_u"]`, and
    `NEP_STATIC["geolon_v"]` to 0-360 before attaching source lon/lat.
  - Converts `hgrid["x"]` to 0-360 before creating PHY OBC `Segment` objects.
  - Prints source, target hgrid, and segment longitude ranges.
- `standalone/initial/nep_to_goa_bgc_ic.py`
  - Converts both NEP source and GoA target `lon` arrays to 0-360 before
    creating BGC IC xESMF weights.
  - Prints source and target longitude ranges.
- `standalone/initial/nep_to_goa_phy_ic.py`
  - Converts NEP and GoA T/U/V `lon` arrays to 0-360 before creating PHY IC
    xESMF weights.
  - Prints source and target longitude ranges.
- `standalone/boundary/BGC/boundary.py` and `standalone/boundary/PHY/boundary.py`
  - Add optional `fill=None`, `fill=False`, and `fill="none"` diagnostic support.
    The default production behavior remains `fill='b'`.
- `standalone/forecast_cgoa/generate_configs.py`
  - Uses v2-specific shared regrid directories:
    - `regrid_ic_phy_shared_v2`
    - `regrid_ic_bgc_shared_v2`
    - `regrid_obc_phy_shared_v2`
    - `regrid_obc_bgc_shared_v2`

## Operational reminders

- Use configs generated from this v2 directory so fresh v2 regrid/weight
  directories are used.
- Do not reuse old xESMF weights generated by the original workflow because the
  coordinate values used to build weights have changed.
- Keep `periodic=False` for the regional NEP source grid.
- Keep `flood=False` in the OBC workflows unless a separate diagnostic study
  justifies changing it.
- The original `tools/IC-OBC-FCST-clean` workflow is unchanged.

## Expected log ranges after conversion

When a v2 run starts building weights, logs should show approximately:

- NEP source longitudes: `156.9` to `255.0`
- GoA hgrid/static/segment target longitudes: `201.3` to `230.1`

If GoA target ranges still print around `-158.7` to `-129.9`, the v2 longitude
normalization is not being used for that run.
